# Project Germania V2 升级路线图

> **定位：AI-powered German Automotive Market Intelligence Platform**

## 1. 项目升级目标

Project Germania V2 将在 V1 已建立的汽车市场价格监测能力之上，逐步从“数据展示 Dashboard”升级为“德国汽车市场智能情报平台”。

升级不以替换或推翻 V1 为目标，而是将现有市场数据、监测结果和可视化能力连接为可解释、可追溯的情报链路：

```text
数据采集 → 数据融合 → 市场监测 → 竞争分析 → AI 洞察 → 战略建议
```

V2 的长期目标是帮助研究者和决策者理解德国汽车市场的价格、注册量、库存、竞争格局与变化信号。所有 AI 洞察、预警和建议都必须清晰区分于来源数据、衍生指标和预测结果，不能被表述为已观察到的市场事实。

## 2. 当前 V1 能力基线

V2 以当前已具备的能力为基础：

- **AutoScout24 数据采集**：包含本地 fixture 管道、合规的 Playwright 搜索页工作流及有边界的批量采集基础；
- **SQLite 数据库**：用于本地持久化、迁移、查询和可审计的数据工作流；
- **Price Monitoring**：支持挂牌价格、库存信号、价格变化、数据导出和只读市场监测；
- **Streamlit Dashboard**：已具备独立展示层基础、共享导航、页面框架与只读 SQLite 服务边界。

这些能力是 V2 的产品底座。后续阶段应扩展其数据覆盖、分析深度和决策价值，而不是删除或另起一套不兼容的实现。

## 3. 三阶段路线

### Phase 1：智能监测平台

**目标**：完善从数据到市场监测的闭环，使 Dashboard 和监测结果成为可靠、可持续更新的日常产品能力。

包含：

- **Dashboard 升级**：将现有 Streamlit 展示层逐步连接至经过验证的数据集，提供市场总览、车型对比、监测结果、数据来源和更新时间；
- **价格监控完善**：扩展 Price Monitoring 的价格变化、库存变化、地区与车型维度比较，并保持挂牌价不等于真实成交价的业务边界；
- **车型评分模型**：基于可解释、配置化的指标构建车型评分或研究价值模型，数据不足时明确返回不足状态；
- **数据自动更新**：建立有边界、可审计、幂等的更新流程，保存原始数据、采集批次、来源信息和失败记录。

**阶段完成标准**：用户可以在 Dashboard 中查看来源明确、更新时间明确、可追溯的市场监测结果；自动更新不会覆盖原始数据或产生重复观察记录。

### Phase 2：汽车市场情报平台

**目标**：将多源市场信号融合为可解释的市场情报，支持主动发现趋势、风险和竞争变化。

包含：

- **新闻 API**：在合规、授权和来源可追溯的前提下接入汽车市场新闻或公开信息源；
- **AI 日报**：依据已验证的结构化数据与可引用的新闻来源生成每日市场摘要，标注数据时间范围、来源与模型生成性质；
- **市场预警**：识别显著的价格、库存、注册量、竞争动态或数据质量异常，并提供规则、阈值和置信度；
- **自动分析报告**：生成可复现的市场、车型、品牌与竞争分析报告，区分原始事实、衍生指标、预测和 AI 解读。

**阶段完成标准**：平台能够将结构化市场数据与合规外部信息融合，输出有来源、有时间范围、可复核的日报、预警和分析报告。

### Phase 3：AI 战略决策平台

**目标**：在经过验证的市场情报之上提供受治理的决策支持，而非把生成式输出直接当作决策结论。

包含：

- **AI Agent**：支持在受限数据范围内检索、解释、比较和汇总市场信息，并展示所依据的来源、计算过程和不确定性；
- **市场进入策略模拟**：基于明确假设模拟细分市场、定价、车型定位、竞争强度与风险情景，不将模拟结果表述为真实预测；
- **竞争策略建议**：结合可追溯的市场事实、模型结果与业务规则，形成带有前提、置信度和人工审核入口的策略建议。

**阶段完成标准**：策略输出可追溯到输入数据、假设和模型版本，支持人工复核，并能明确显示适用边界与不确定性。

## 4. 开发原则

1. **不推翻 V1**：保留并复用 AutoScout24、SQLite、Price Monitoring 和 Streamlit Dashboard 等现有能力。
2. **基于现有架构升级**：继续使用已有的数据分层、配置管理、数据质量、原始数据留存和可审计工作流。
3. **保持数据库兼容**：新增数据实体、字段、迁移和查询时兼容 SQLite 本地开发与 PostgreSQL 后续部署；不得破坏现有数据语义和历史记录。
4. **分阶段开发**：每个阶段先定义数据来源、业务口径、质量规则、验收标准和风险边界，再实施下一阶段。

同时，V2 持续遵守项目既有原则：数据真实性优先；挂牌价不等于成交价；KBA 新车注册量不得被误表述为企业真实销量收入；AI 输出、预测和策略建议必须明确标记；不得绕过验证码、登录、访问控制或网站反自动化保护。

## 5. 实施边界

本路线图是产品与文档规划，不代表 Phase 1、Phase 2 或 Phase 3 的功能已经开发完成。后续每项功能应以独立任务实施，并配套数据设计、测试、合规审查和文档更新。
